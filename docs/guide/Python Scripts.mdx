# Python Scripts

`pepyton` starts a `.py` file that already sits in the Python folder. The registered name is `PEPyton`.

Default folder: `plugins/PEUtils/pythonScripts/`.

The command does not return stdout, stderr, or the exit code to the Denizen queue. It also does not wait. `execute` schedules `PythonUtils.runPythonScript` on an async Bukkit task and then returns. The script line after `pepyton` runs while Python may still be starting.

## Process

The async task builds this process:

```text
python3 <absolute path of the .py file> <argument> <argument> ...
```

The working directory is the folder that contains the `.py` file, so a script can open files next to itself with a relative path. Arguments are separate process arguments. They are not one shell string. The plugin does not invoke a shell.

`python3` must be on the PATH of the server process. A missing interpreter, a missing permission, or a Python exception prints a Java stack trace from the async thread. Denizen debug does not show that failure.

The task calls `waitFor` and ignores the exit code. Standard output and standard error are never read.

Both `filename` and `arguments` are required. There is no zero-argument form. Pass a single dummy token if the Python file ignores argv.

If the file is missing, Denizen prints `Failed to run python file, that file does not exist`.

If either argument is missing, the plugin throws `You need to specify a id, filename and world.` That sentence was copied from the map command. The check itself requires `filename` and `arguments`.

## Example

Put `plugins/PEUtils/pythonScripts/hello.py` on the server:

```python
import sys
print(sys.argv[1:])
```

Call it from Denizen:

```yml
- pepyton filename:hello.py arguments:alpha|beta
```

That starts `python3` with argv `alpha` and `beta`. The print goes to the process output, which this plugin does not forward. You will not see it in Denizen.
